\section{Introduction}
Edge inference is now constrained less by peak arithmetic throughput than by the quality of resource allocation under strict silicon and energy envelopes. In the Ethos-U55 class of deployment targets, designers cannot scale every subsystem independently: MAC array width, shared SRAM capacity, local scratchpad size, and memory bandwidth all compete for the same area and power budget \cite{b7,b8,b9}. The practical problem is therefore not ``how to make the accelerator bigger,'' but how to allocate a fixed budget so that end-to-end workload cost is minimized. This is particularly acute for modern mixed workloads such as YOLO-World \cite{b10}, where early high-resolution convolutions, deep backbone convolutions, text-projection layers, and detection heads exercise different parts of the architecture and can shift the bottleneck from compute to movement and back within a single model.

Our project begins from two milestones of infrastructure and empirical results, and then advances to a full constrained co-design study. In Milestone 1, we built a calibrated Ethos-U55-style model with explicit energy and area defaults grounded in published architecture anchors and energy-hierarchy priors, including Arm Ethos documentation, Horowitz-style operation costs, and movement-centric analysis from Eyeriss and related surveys \cite{b1,b2,b4,b7,b8,b9}. In Milestone 2, we unified architecture and workload evaluation into a single sweep framework and established initial trends: moving from lower to higher memory-bandwidth presets consistently reduced latency/EDP for key layers, while increasing MAC count alone exhibited diminishing returns unless memory service was also improved. Those findings motivate the final direction: treat edge accelerator design as a budget-constrained Pareto problem, not a SKU selection problem.

The final study addresses a gap in both industrial SKU-centric practice and much of prior automated co-design work. Reinforcement-learning and structured co-design frameworks have shown the value of larger search spaces \cite{b5,b6}, but in this setting we prioritize physically interpretable knobs and transparent budget accounting over opaque search policies. Concretely, we evaluate candidate designs beyond published Ethos points, enforce explicit area and power constraints, and analyze performance over a representative probe set chosen to span distinct bottleneck regimes. The resulting contribution is a set of architecture-level design rules for edge NPUs under realistic constraints: when to spend budget on compute width, when to spend it on memory capacity, when bandwidth is the dominant lever, and how those priorities change across budget tiers and workload shapes.

\section{Technical Contributions}
This work contributes a complete, budget-aware architecture-workload evaluation flow for Ethos-U55-class edge accelerators and a set of experimentally grounded design conclusions derived from that flow. The architecture model captures the three components that dominate edge tradeoffs in this class: the MAC array as the primary compute engine, shared on-chip SRAM as the principal reuse buffer and traffic-reduction reservoir, and local scratchpad as the short-distance staging layer that enables low-cost inner-loop reuse \cite{b1,b4,b7,b8}. On top of this hierarchy, we model two distinct memory-service regimes, corresponding to low-bandwidth and high-bandwidth embedded operation, because sustained throughput in this domain is determined by how reliably data can feed compute rather than by peak MAC count alone \cite{b1,b3,b4}.

Our methodology is intentionally structured around heterogeneous workload stress rather than single-layer microbenchmarks. We use YOLO-World as the base workload \cite{b10} because it contains materially different layer classes in one model: stem and detection-head convolutions that are movement-sensitive at large spatial extent, deeper backbone layers with stronger reuse opportunities, and text-projection layers with dense matmul characteristics. To keep exploration tractable without collapsing to a single bottleneck layer, we use a fixed five-layer probe set \((T1, T7, T10, T16, T19)\) that captures these regimes and covers about one-third of total model MACs. This choice follows first principles from the class: if conclusions are to generalize across the model, the evaluation set must include both movement-dominated and compute-dominated phases, not only one side of the roofline \cite{b1,b4}.

From an optimization perspective, the core technical contribution is constrained selection over interpretable architecture tuples rather than unconstrained ranking. Each candidate is evaluated with the same mapping objective and assumptions, then filtered by fixed area and power budgets before ranking by energy-delay behavior. This is crucial for edge relevance: many points that look attractive in unconstrained EDP are nonviable once power or area is enforced. We therefore report not only best EDP points, but also the identity of the selected tuple and utilization of each constraint, which reveals whether a regime is compute-limited, memory-limited, area-limited, or power-limited. In practical terms, this produces guidance that can be used to design the next accelerator revision, not just to explain one benchmark run.

A second contribution is explicit workload-shape co-design under fixed hardware, used to test whether architecture conclusions remain stable when workload pressure changes. We vary input resolution on fixed architecture points and analyze normalized efficiency trends to distinguish true hardware-workload matching gains from trivial operation-count reduction. This allows us to answer a question that is usually hand-waved in edge papers: whether an architecture that wins at one operating point remains efficient when the deployment team inevitably changes resolution for latency or power reasons.

Finally, we include a robotics-oriented extension with an explicit action-decoder specification appended after the 21-layer YOLO-World perception stack. The added decoder is a three-layer MLP modeled as T21--T23 with batch size one and sequence length one (a pooled feature token), using dense projections 512 to 512, 512 to 256, and 256 to 64. In concrete terms, this corresponds to 262,144 MACs at T21, 131,072 MACs at T22, and 16,384 MACs at T23, for a total of 409,600 MACs. The weight matrices contain 409,600 INT8 parameters in aggregate, which is about 400 KB of raw weight storage before packing/alignment. Functionally, T21 serves as feature-space adaptation from vision backbone output to control-oriented latent space, T22 performs dimensionality compression to improve separability under tight memory budgets, and T23 produces a compact 64-dimensional action representation suitable for downstream control logic. Because the baseline YOLO-World stack is dominated by multi-hundred-million-MAC spatial convolutions, this decoder adds less than 0.02\% incremental compute while still injecting a qualitatively different operator regime (small-batch dense control inference) into the mapping problem. This preserves a unified area/power-constrained evaluation framework while making the workload materially more representative of embodied edge deployments where perception and action inference co-exist on the same NPU budget. Taken together, these pieces move the project from milestone-level exploration to a publishable hardware-architecture study: calibrated model assumptions, constrained and reproducible design-space evaluation, heterogeneous layer coverage, and interpretable design conclusions tied directly to edge budgets.


\section{Experiment Setup}

\subsection{Modeling Assumptions and Validity Checks}
Our experimental conclusions are derived under explicit modeling assumptions, each chosen to preserve architectural signal while keeping search tractable. On-chip memory is modeled as a software-managed hierarchy (FLASH \(\rightarrow\) SRAM \(\rightarrow\) scratchpad) rather than a cache-coherent hierarchy; for this workload class, layer execution is statically scheduled and access patterns are structured, so replacement-policy and tag overheads are second-order relative to aggregate tensor movement. FLASH is modeled as effectively unbounded upper memory, SRAM and scratchpad are explicitly capacity-limited, and scratchpad placement is restricted to intermediate tensors to reflect practical local-storage use and to avoid infeasible weight-residency assumptions at this scale. Bandwidth is represented through two presets, and per-level latency is modeled from action counts and service rates, which captures contention at the level of sustained traffic but not cycle-accurate arbitration effects.

At the compute and control level, MAC latency is modeled from operation count and array width at fixed clock, while leakage, NoC/control overhead, and host-side orchestration energy are not separately parameterized. In addition, mapping is performed one einsum (layer) at a time and aggregated, rather than simulating a fused end-to-end command stream. These choices mean our numbers should be interpreted as architecture-comparative efficiency estimates under controlled assumptions, not as sign-off silicon power traces. Broad design-space search also uses a fixed five-layer probe surrogate (\(T1,T7,T10,T16,T19\)) instead of full 21-layer remapping at every candidate point; this is a computational tradeoff intended to preserve cross-regime behavior (early spatial convolution, mid/deep convolution, text projection, detection head) while maintaining feasible runtime.

Within the scope of this paper, we therefore interpret results as comparative architectural evidence under controlled assumptions rather than as absolute silicon sign-off numbers. The key validity criterion is consistency of trends across experiments under a fixed modeling framework: all candidate designs are evaluated with the same hierarchy assumptions, objective definitions, and budget filters, so relative deltas in energy, latency, and EDP remain meaningful for allocation decisions. A broader sensitivity analysis on parameter perturbations (e.g., SRAM/FLASH energy variation) is left as a direct extension for future work.

\subsection{Experiment 1: Fixed-Budget Hardware Allocation and Pareto Frontier}
Our first experiment asks a direct architecture question: under a fixed edge budget, which resource allocation minimizes end-to-end cost for a representative YOLO-World workload slice? We evaluate an Ethos-U55-class design space where the key knobs are compute width (MAC count), shared on-chip capacity (system SRAM), local buffering (scratchpad), and memory-service capability (bandwidth preset). In this context, an Ethos ``SKU'' refers to one product point in Arm’s published family (for example, U55-128 or U55-256), each corresponding to a discrete tuple of compute width and local memory provisioning. The motivation for moving beyond SKU points is that SKU grids are coarse by construction; they are designed for product segmentation, not necessarily for workload-optimality under a specific area and power envelope.

The architectural distinction between the two bandwidth presets is central to this experiment. The \texttt{deep\_embedded} preset models a lower-memory-throughput regime intended for stricter embedded power envelopes, while \texttt{high\_end\_embedded} models a significantly higher SRAM/FLASH service rate. Classically, this is the difference between a design that is compute-provisioned but feed-limited versus one that can keep the array occupied. In dataflow terms, larger or faster memory systems improve temporal and spatial reuse realization by reducing refill pressure and long-latency accesses; wider MAC arrays only translate into lower latency when data supply keeps pace. This is exactly the bottleneck crossover discussed throughout the course: peak arithmetic throughput is not the same as sustained throughput.

Our mapping formulation is therefore explicitly movement-aware rather than compute-only. For each candidate architecture, layer mappings induce action counts at FLASH, SRAM, scratchpad, and MAC levels, and total layer energy is computed as the sum of action-weighted terms across those levels. Conceptually, this decomposes the objective into compute and hierarchy movement components, where FLASH/SRAM/scratchpad terms capture dataflow quality and MAC terms capture arithmetic work. The experiment’s hardware-allocation claim is validated only if improvements in EDP coincide with reduced movement pressure (lower movement-driven share and/or lower movement latency contribution), not merely with larger arrays. Conversely, if EDP falls while movement terms remain dominant and unchanged, the claim that bandwidth and memory hierarchy are the governing levers would be weakened. This criterion gives a direct logical test for whether observed gains are truly dataflow/memory-hierarchy driven.

To make this test tractable but still representative, we use five probe layers from YOLO-World, chosen to span distinct operator regimes rather than only one family of convolutions. Layer T1 is the backbone stem convolution (large spatial map, low channel depth), which is typically bandwidth-sensitive because activation movement is high relative to arithmetic reuse. T7 and T10 are deeper backbone convolutions with progressively different reuse and channel structure; these layers probe the transition from movement-dominated behavior toward stronger compute utilization. T16 is the text-side feed-forward projection (dense matmul-like behavior), which has very different reuse and memory-access regularity than spatial convolutions. T19 is the detection-head convolution with very large compute volume at high spatial resolution, and is often one of the dominant contributors to total cost. This set therefore captures early-spatial, mid/deep-conv, text-projection, and head behavior in one sweep and avoids overfitting conclusions to a single layer type.

For fairness, we compare all candidate points against Ethos-U55-like baselines from prior sweeps (including 128-MAC/384KB and 256-MAC/384KB classes), while holding workload definition, mapping objective, process assumptions, and area/power models fixed. Area is evaluated from the same analytical model for every candidate as NPU core plus system SRAM plus scratchpad; average dynamic power is computed from mapped energy and latency, then used to filter budget-violating points. The principal outcome metric is EDP, with total energy and total latency reported separately to expose whether a gain is compute-driven, movement-driven, or both. This metric set is sufficient to answer the experiment question because EDP captures the joint efficiency objective, while energy, latency, area, and power disambiguate why one architecture wins and whether it is feasible in the targeted edge envelope.

\subsection{Experiment 2: Workload-Shape Co-Design Under Fixed Hardware}
The second experiment addresses a complementary question: if hardware is fixed, how much of the remaining inefficiency is due to workload shape, and how does that dependence vary by architecture point? We hold hardware constant at three representative provisioning levels (tight, preliminary best, and memory-rich), then vary input resolution (640, 448, 320) while keeping the same probe-layer semantics. This is a deliberate workload-side intervention that changes spatial tensor sizes and therefore memory traffic, rather than changing model family or retraining objective.

The scope boundary is explicit: we fix model precision and architecture semantics to isolate hardware-allocation effects. In practice, arithmetic precision (INT8-style energy model), operator definitions, and mapper objective remain unchanged across workload variants; only spatial problem size is rescaled through input resolution. We therefore do not claim algorithmic compression gains from pruning, quantization sweeps, or retraining in this section. Instead, this experiment isolates the hardware-visible effect of workload shaping on residency, traffic, and utilization under a constant architecture contract.

The layer-level rationale follows first principles of data movement and reuse. For T1 and T19, shrinking spatial dimensions reduces activation footprint and movement pressure substantially; these are exactly the layers where memory hierarchy stress dominates and where improved fit in SRAM/scratchpad should yield disproportionate gains. T7 and T10 serve as intermediate checks: they are still convolutional, but their reuse structure differs from the stem and head, so they help identify whether benefits are broadly spatial or limited to extreme layers. T16 is intentionally included as a counterpoint, since text-side dense projection does not scale with image resolution in the same way and therefore should exhibit smaller relative benefit from spatial downscaling. This contrast is important: a credible co-design study must show both where an intervention helps and where it should not help.

Methodologically, this experiment reflects core class ideas about working-set sizing, memory-level fit, and arithmetic intensity. Lowering resolution reduces not only total MACs but also activation residency requirements, which can shift execution from upper-memory traffic toward lower-memory reuse. To avoid reporting a trivial ``smaller model is faster'' result, we track EDP-per-MAC in addition to raw EDP, energy, and latency. EDP-per-MAC is the key interpretive metric here: if it improves, efficiency per unit computation improved, which indicates better hardware-workload matching rather than only reduced workload volume. Per-layer latency-speedup trends are also reported to verify that gains are concentrated where theory predicts (movement-sensitive spatial layers) and muted where theory predicts (text projection layer). Together these metrics answer the experiment question by separating scale effects from architectural efficiency effects and by revealing whether workload reshaping is a robust lever across hardware regimes or only a patch for under-provisioned memory systems.

\subsection{Experiment 3: Area--Power Constraint Regimes and Binding-Limit Analysis}
The third experiment asks which constraint is actually binding in practice: silicon area, power, or both depending on operating regime. Instead of treating budget as a single scalar, we evaluate a 3-by-3 grid of area and power caps and select the best feasible architecture in each cell. This is a constrained-design experiment, not a free-form sweep, and its purpose is to characterize regime changes in the optimizer’s choice.

The architectural justification is straightforward. Area budgets govern how much compute and on-chip storage can exist simultaneously; power budgets govern how aggressively those resources can be exercised in sustained operation. A design that is optimal under area-only filtering can become infeasible or suboptimal once power is enforced, especially when high-bandwidth or high-activity settings raise dynamic power. Conversely, under strict area limits, the dominant tradeoff may be between compute width and memory capacity even when power headroom exists. This area-versus-power tension is a central edge-design concept from class: real accelerators are constrained by both physical provision and dynamic operation, and the active limiter shifts with regime.

To make that shift explicit, each grid cell records not only the winning architecture and its EDP, but also area utilization and power utilization relative to the cell cap. These utilization metrics indicate which constraint is near saturation and therefore likely binding. Reporting only EDP would hide this mechanism; reporting only utilization would hide outcome quality. The combined metric set (best-cell EDP, selected tuple, throughput proxy from latency, and area/power utilization) directly supports the method question by showing when relaxing area helps, when relaxing power helps, and when one of those relaxations is largely irrelevant because the other constraint dominates. In short, Experiment 3 converts ``better under tighter budgets'' from a qualitative statement into a regime map that can be used to state conditional design rules for future Ethos-U55-class edge accelerators.
